# Assets

## Block styles and scripts

WordPress reads each block's asset metadata from its `block.json` file and enqueues the assets for that block. Declare asset files with paths relative to the block directory:

```json
{
  "editorScript": "file:./index.js",
  "editorStyle": "file:./index.css",
  "style": "file:./style-index.css",
  "viewScript": "file:./view.js"
}
```

Use `editorScript` and `editorStyle` for the editor, `style` for the editor and frontend, and `viewScript` for the frontend. WordPress uses the corresponding `.asset.php` files generated by the build to load script dependencies and versions.

The framework registers blocks from the directory configured with `loadBlocks()`. Keep each block's `block.json` and its referenced files together in that block's directory. `setDistDir()` changes the asset directory used by the framework's on-demand helpers and the default location of `blocks-manifest.php`; its default is `dist/`.

The optional `blocks-manifest.php` generated by `wp-scripts build --blocks-manifest` lets WordPress load block metadata from a single file. The framework uses it from the configured dist directory when present. This metadata optimization requires WordPress 6.7 or later; without a usable manifest, block registration reads each `block.json` directly.

## Assets loaded on demand

`BaseBlock` provides helpers for assets that should only load when a block is rendered:

* `addInlineCss($cssFile)` reads a CSS file relative to the configured dist directory and adds it inline.
* `addJs($jsFile, $dependentHandle)` enqueues a JavaScript file relative to the configured dist directory. The optional dependent handle must already be registered.

These helpers are useful for styles or scripts that are specific to a server-rendered block. For regular block assets, declare the files in `block.json` so WordPress can manage their loading.
